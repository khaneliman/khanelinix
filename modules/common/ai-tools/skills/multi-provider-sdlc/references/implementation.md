# Implementation

1. Read contributor canon; capture relevant Git baseline and dirty paths;
   classify risk.
2. Form the smallest executable plan. Parent owns architecture, integration,
   conflict resolution, and final judgment.
3. Dispatch bounded write batches with exact paths, constraints, validation, and
   exit criteria. Split only disjoint write scopes; never duplicate
   implementations for provider diversity.
4. Inspect and integrate returned changes. Preserve unrelated work and reject
   scope expansion.
5. Continue into validation and review playbooks without a user checkpoint.

Use one best-fit write route per batch. Opus may implement; read-only behavior
is a phase assignment for deliberation and review, not a model-level
restriction. Use planning-with-files autonomous mode only when persistence
materially helps.
